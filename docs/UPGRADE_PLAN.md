**照面 Glimpse 升级改造方案**

日期：2026-10-18
基线：本地 v1.9.0，提交 `542724b`
状态：1.10–1.12 的功能与工程升级已实现，当前版本为 1.12.0。下文保留原始方案，末尾记录各阶段实际交付。原方案中的工作量和性能数字是目标，不是实测结论。

**产品方向**

把照面打磨成随叫随到的视觉找页工具：看画面能认出，记得几个字能搜到，需要整理时顺手完成。

保留现有 React、虚拟网格和本地处理方式，重点改善预览、查找与操作反馈。默认界面维持两行轻量工具区和缩略图墙，主要功能不要求账户、联网或模型。

**一、当前基础与主要问题**

已有自动截图、上次浏览预览、即时平滑放大、标题/网址搜索、标题快捷词、网站与窗口筛选、多选关闭、关闭撤销、窗口合并和位置恢复。升级应继续打磨这些能力，不将其重复计为新增功能。

| 代码检查发现 | 用户受到的影响 | 改造方向 |
|---|---|---|
| 截图失败统一进入重试，卡片缺少具体原因 | 不知道没图是尚未浏览、权限不足还是暂时失败 | 建立可诊断的预览状态和恢复方式 |
| 每 30 秒恢复检查尝试采集聚焦窗口，未判断页面有无新变化 | 静止页面也可能被反复截图和写入 | 事件驱动、变化标记、刷新间隔与低频兜底 |
| 打开总览前的截图调用只是入队，没有等待队列完成 | 实际仍可能显示上一帧 | 明确任务完成信号，但不阻塞打开总览 |
| 同一截图分别随标签索引和网址索引保存、计数 | 缓存预算不等于可保存的页面数量 | 一份图像、多个索引，保留现有隔离规则 |
| 网站筛选是隐藏滚动条的横向长列表 | 网站很多时，后面的入口难发现 | 可搜索的网站选择菜单 |
| 窗口筛选主要从卡片编号进入 | 未找到卡片时，难以先缩小窗口范围 | 直接可达的窗口选择菜单 |
| 每个标签更新事件都触发全量查询，搜索索引依赖整个标签数组 | 密集事件可能产生多余查询和重建，影响需测量 | 合并事件、增量更新、独立维护搜索索引 |
| 合并窗口立即处理全部普通窗口，而非筛选结果 | 作用范围不直观，也不能选择目标 | 明确目标、数量和范围的紧凑操作面板 |
| Overview.tsx 同时承担同步、搜索、操作、撤销和位置记忆 | 小改动容易影响多处交互 | 按现有职责逐步拆分，保留回归检查 |

以上为静态检查发现，不代表已经测得性能瓶颈。

**二、必须保持的体验约束**

- 延续炭灰背景、灰白文字和克制的状态色，不使用蓝色主色。
- 鼠标进入即开始放大；连续划过可顺畅反向过渡；无图卡片保持同样反馈。
- 默认卡片没有常驻亮边框，键盘操作仍有清楚的焦点。
- 默认排列稳定，后台更新不自动洗牌；菜单和通知不挤动网格。
- 搜索框短小，快捷词常驻其右侧、按空间折叠，弹层跟随按钮。
- 无常驻操作教学、大型侧栏或额外首页。低频功能按需出现。
- 批量操作对象与结果清楚，部分失败可继续处理，不用笼统错误覆盖成功项。

**三、第一优先级：预览可靠、后台安静**

建立内部完整、对用户简洁的预览状态。

| 状态 | 默认呈现与恢复方式 |
|---|---|
| 本次浏览已有预览 | 正常截图，不额外贴状态标签 |
| 只有较早预览 | 保留图像和低干扰标记，详情可看更新时间，再次浏览后更新 |
| 尚未采集 | 显示网站、标题和“浏览后生成预览”，点击仍正常进入页面 |
| 权限不足 | 说明具体缺少的权限；文件页面说明需开启文件访问 |
| 暂时采集失败 | 同一页面有图则保留；只有符合截图条件时才提供重试 |
| 隐身或被排除的网站 | 标明不保存预览，仍可查找和操作标签 |
| 当前策略不采集的页面类型 | 显示网站图标与标题，不反复重试 |

状态按标签、完整网址和导航版本绑定。导航到新网址不能沿用旧页面图像；关闭、权限变化或采集完成时清理过期状态。不能仅凭黑色或纯色图像认定失败，合法页面也可能如此。

采集策略分五步调整：

1. 标签激活、加载完成、页面操作等事件标记待更新，连续事件合并，优先处理用户正在看的页面。
2. 同一页面设置最短刷新间隔；已知无变化则跳过。少量采集元数据进入会话存储，工作线程重启后仍能去重。
3. 固定高频兜底改为较低频恢复检查，初始候选为 2～5 分钟，实测后调整。视频、动态看板等不能靠滚动/点击覆盖的场景保留兜底或手动刷新。
4. 打开总览优先展示缓存，截图有完成通知。若尝试在遮挡原窗口前采集，只给予短暂等待预算，超时立即打开；实测遮挡、多屏和快速切换，不能将“入队完成”当作“截图完成”。
5. 保留截图前后页面校验、串行限速和有界重试；区分权限拒绝、不符合条件与暂时失败。

Chrome 的 captureVisibleTab 只能捕获指定窗口当前活动标签的可见区域，最多每秒调用 2 次。它不能直接遍历截图任意未激活标签，因此继续采用“随浏览逐步补齐”的方式，不自动轮流切换标签来补图。[Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab)

应区分平台能力与产品策略：当前插件主动限制采集范围，并非所有内部页面在 API 层都绝对无法截图。维持保守的自动采集策略，不增加调试器或录屏权限。

缓存改造先验证收益，再迁移：图像以 Blob 保存，标签和网址记录引用同一份图像；按实际图像大小及索引开销统计预算。继续保持完整网址匹配、同会话不同标签隔离和隐身排除。优先淘汰过期及不再使用的图像，所有保留策略受总预算约束。旧格式分批或按访问迁移，写入成功前不删除原记录，失败仍可读取旧缓存。

后台继续允许休眠，关键状态不能只放全局变量，也不应靠持续轮询保活。[Chrome Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

**四、查找与界面：减少寻找入口的成本**

| 区域 | 内容与交互 |
|---|---|
| 第一行左侧 | 短搜索框、快捷词、更多词；低质量词少显示 |
| 第一行右侧 | 标签数量、更多菜单；整理、设置和快捷键入口按需出现 |
| 第二行左侧 | 全部窗口、全部网站、排列方式；条件可直接清除 |
| 第二行右侧 | 多选；进入后原位显示所选操作，窄屏收纳低频操作 |
| 主体 | 缩略图网格，默认位置稳定，保留虚拟化 |
| 临时反馈 | 底部操作结果、撤销和可处理错误，不常驻占位 |

网站菜单显示图标、域名、数量，并可输入网站名筛选，替代难以发现的横向长列表。窗口菜单显示“窗口 2 · 18 个页面”等信息，配代表页面标题辅助辨认；不猜测“工作”“娱乐”等主题。卡片上的窗口入口继续保留。

默认按原位置查找，增加可选的“最近使用”排列：进入时生成快照，当前总览不因后台事件持续重排。优先使用浏览器访问时间；lastAccessed 从 Chrome 121 起提供，当前最低版本为 120，缺失时需回退，不能无说明地提高版本门槛。[Chrome Tabs 属性](https://developer.chrome.com/docs/extensions/reference/api/tabs#type-Tab)

搜索在现有 Fuse 模糊匹配前增加明确优先级：标题/域名准确匹配优先，其次全部关键词命中，最后放宽为模糊匹配。同等级结果保持稳定。命中片段用字重或浅底色强调，避免整卡高亮。

快捷词仍由本地标题提取，重点修剪低信息量词、避免同主题占据过多位置、保留有效词的顺序。无可靠候选时少显示，不为“智能”加入模型或复杂搜索语法。

无结果时区分“全局不匹配”和“被条件排除”。后者提供“在全部页面查找”，保留搜索词。快捷词继续采用现有的全局搜索语义，并同步清除筛选显示。

卡片只补充有用状态：固定、发声、浏览器休眠。提供完整标题查看方式，帮助分辨标题前缀相同的页面；不改变网格尺寸，不延迟放大。

键盘继续保持输入即搜索、方向键选择、Enter 定位；Esc 先退出当前弹层或多选，再清搜索、清筛选，最后退出总览。统一新增菜单的焦点返回、边缘避让和输入法行为。

**五、第二优先级：顺手整理，范围清楚**

| 能力 | 建议行为与边界 |
|---|---|
| 移动所选 | 多选后移动到指定或新建窗口，只处理已选页面，不关闭后重开 |
| 查看重复页 | 在整理菜单显示重复组，检查后关闭所选副本；按完整网址匹配，保留查询参数和 hash，不自动关闭 |
| 改进窗口合并 | 紧凑面板列出目标窗口、来源和数量，再执行；明确作用于全部窗口，普通与隐身分别处理 |
| 批量关闭 | 保留逐项结果、失败重试和整批撤销；全选结果仍代表当前结果，改变筛选会清除选择 |

完整选中的标签组整体移动；只选中组内部分页面时，明确告知这些页面将离开原组，不带走未选页面。覆盖固定标签、隐身隔离，以及用户在操作中自行移动页面的情况。

重复组只提供建议保留项：固定、正在发声或最近使用页面优先。默认不将固定、发声页面勾选为待关闭项。同网址也可能有不同的表单或页面状态，最终关闭对象由用户决定。

关闭撤销继续保留，但不承诺任意数量页面都完整恢复。Chrome 最近关闭会话列表有数量限制；会话不可用时只能尝试重新打开网址，并明确说明降级。[Chrome Sessions API](https://developer.chrome.com/docs/extensions/reference/api/sessions)

窗口合并的完整撤回涉及窗口重建、标签位置和标签组恢复，首批不承诺此能力，避免将部分回滚包装为“完全撤销”。

**六、轻量设置与工程维护**

设置从更多菜单进入，控制在四组：

- 显示：标准/紧凑两档卡片密度，悬停预览默认开启，遵从系统减少动态效果偏好。
- 预览：自动更新、暂停采集、排除网站；排除网站同时清除已存预览，暂停采集与删除已有图像分开表达。
- 本地缓存：查看大致占用，清空全部或指定网站缓存；恢复后按正常浏览重建。
- 快捷键与关于：复用 Chrome 快捷键设置入口，展示版本、隐私说明与反馈地址。

设置只保存在本机，不加入自由主题编辑器或大量截图参数。以后若新增关闭记录、最近使用信息的持久保存，需要明确内容和期限，并更新隐私说明。

| 代码位置 | 改造重点 |
|---|---|
| src/background/service-worker.ts、captureQueue.ts | 任务结果分类、事件合并、空闲跳过、恢复与完成通知 |
| src/lib/thumbnailCache.ts | 共享图像、索引隔离、预算淘汰、兼容迁移 |
| src/lib/tabManager.ts | 补齐 pinned、audible、discarded、groupId 等必要状态 |
| src/overview/Overview.tsx | 抽离标签同步、搜索筛选和批量操作，保持数据契约简洁 |
| SearchBar.tsx、titleKeywords.ts | 搜索优先级、候选质量和稳定排序 |
| TabCard.tsx、src/index.css | 预览状态、必要页面状态、密度及焦点规则 |
| batchActions.ts、undoClose.ts | 明确范围的移动/重复页整理，保留部分失败和恢复逻辑 |
| tests/ 与打包流程 | 统一检查入口、真实扩展冒烟检查、版本与安装包校验 |

全量查询留给初始化、操作后核对和必要纠正，普通更新尽量只修改对应标签。搜索索引仅对标题/网址变化更新，缩略图变化不重建索引。逐步替换，不同时更换框架和虚拟列表。

源码未发现 framer-motion、clsx、tailwind-merge 的使用，后续确认构建和脚本无引用后可移除。主要收益是减少安装与维护负担；未使用依赖可能已被构建工具剔除，不能预先承诺显著缩小发布包。

补齐可重复的检查入口和 Windows 打包方式，让贡献者能在项目内安装测试依赖。持续集成至少运行构建、静态检查和现有逻辑测试，文档明确区分模拟 Chrome API 测试与真实扩展验证。

**七、实施顺序与交付边界**

建议小步发布。以下是单人连续开发、包含对应验证的初步工作量，待基线测量后修订，不是固定上线承诺。

| 阶段 | 范围 | 完成标志 | 粗估 |
|---|---|---|---|
| 基线检查 | 固定环境，记录找页耗时、截图频率、查询/索引次数、首屏和搜索响应 | 有可对比的 v1.9.0 基线和问题样本 | 1～2 个工作日 |
| 1.10：可靠与节制 | 预览状态、采集策略、事件合并、存储迁移验证 | 失效原因清楚、空闲采集下降、升级缓存可用 | 4～6 个工作日 |
| 1.11：更快找到 | 网站/窗口菜单、搜索优先级、最近使用排列、顶部收敛、必要设置 | 找页路径缩短，原有交互无退化 | 4～6 个工作日 |
| 1.12：轻量整理 | 移动所选、重复组查看、合并范围面板、发布检查完善 | 作用对象和结果清楚，部分失败可处理 | 4～6 个工作日 |

先做 1.10，再根据多窗口实际使用反馈决定 1.11 的细节。缓存迁移若不能充分验证，可独立后置，不能阻塞预览状态和无效采集优化的发布。

第一阶段不加入账户/云同步、书签库、会话工作区、AI 聊天、正文采集/OCR、自动关闭或休眠页面。模型能力等到本地搜索存在明确瓶颈时，再单独评估。

**八、验收标准**

记录测试机、浏览器版本、缩放和显示分辨率；覆盖 10/100/500 个标签及多窗口样本，另测 200% 缩放、360px 窄窗和减少动态效果模式。性能先测基线再冻结目标，以下是初始目标。

| 维度 | 方法与目标 |
|---|---|
| 查找效率 | 同一组“记得画面/几个词/窗口/刚访问”的任务对比基线，目标中位完成时间下降约 30% |
| 总览打开 | 已有缓存的 100 标签样本，首屏可操作时间目标 P95 ≤ 500ms；无图时标题和搜索先可用 |
| 搜索 | 500 标签样本，输入至结果更新目标 P95 ≤ 100ms，至少测 30 次，区分索引初建与后续输入 |
| 预览更新 | 已加载、可采集且无拥塞时，激活后目标 2 秒内有可用预览；未访问、无权限和失败单列统计 |
| 空闲消耗 | 聚焦普通静态页面、总览关闭，10 分钟无交互；预热后截图目标 ≤ 2 次，无无界重试或持续保活 |
| 动画布局 | 连续划过 20 张卡片、边缘与无图卡片；按钮可点、菜单贴近按钮、提示不挤动网格 |
| 数据正确性 | 快速切页、导航中截图、同网址多标签、重启、工作线程恢复与缓存迁移均不串图 |
| 批量操作 | 范围、分组/固定、隐身、部分失败、重复点击和目标窗口消失均有明确结果，未选页面不被移动 |
| 体积维护 | 比较正式发布包而非 node_modules；不新增远程运行时或默认模型依赖，包体增加超过基线 20% 时解释来源 |

自动化复用现有六组测试；真实扩展在隔离浏览器资料目录中验证权限开关、文件访问、重启、截图和窗口操作。真实操作试验使用专门的测试页面。

**建议首批交付**

先完成“预览状态可解释、空闲少截图、事件更新少做无用功”。这直接回应最初的缩略图痛点，也给后续查找和整理留下性能空间。默认界面只增加能缩短找页路径的入口，功能数量不作为升级完成度的衡量标准。
